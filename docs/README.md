# OctoAcme Project Management Docs

This repository contains the core project management guidance used by OctoAcme. The goal is to provide a lightweight, consistent operating model for initiating, planning, executing, releasing, and improving work across cross-functional projects.

## Overview

OctoAcme follows a simple lifecycle that moves from initiation through planning, execution, release, and continuous improvement. The team emphasizes customer value, clear ownership, iterative delivery, measurable outcomes, and transparency across the project portfolio. Each project begins with a clear problem statement, stakeholder alignment, and a decision gate before formal planning begins.

During planning, the team defines scope, milestones, dependencies, and backlog priorities, along with acceptance criteria and a Definition of Done. Execution is managed through standups, weekly delivery reviews, issue tracking, and CI validation. Risk management, communication, and QA are treated as core parts of delivery rather than separate afterthoughts. Releases are verified carefully, with rollback planning and post-deployment checks, and each milestone ends with a retrospective to capture lessons and turn them into action items.

## Key roles

OctoAcme relies on clear role ownership across the project lifecycle:
- Project Manager: coordinates schedules, risks, communication, and project artifacts
- Product Manager / Product Lead: defines outcomes, prioritizes the backlog, and measures success
- Developers: implement features, maintain quality, and contribute to technical planning and testing
- QA / Testing: validate acceptance criteria and software quality
- Stakeholders: provide input, alignment, and approval

## Core workflows

The process docs in this repository describe the following recurring practices:
- Initiation: confirm the business problem, align stakeholders, and decide whether to move forward
- Planning: create a backlog, define scope, estimate work, and map milestones
- Execution: run daily/weekly delivery routines, review progress, and resolve blockers
- Release & deployment: validate readiness, ship safely, communicate outcomes, and monitor issues
- Retrospective & continuous improvement: document lessons learned and turn them into improvements

## Quality and communication

OctoAcme expects disciplined delivery practices, including:
- Unit, integration, and smoke testing where appropriate
- CI checks for tests, linting, and security scanning
- PR review standards with acceptance criteria and approvals
- Clear stakeholder updates and escalation paths for risks or blockers
- Standardized documentation of milestones, risks, and release readiness
